# Tu Mesa Bot: Asistente Web para Atención en Mesa

## Descripción del Proyecto
* **Contexto:** Pequeños y medianos restaurantes con alta demanda que presentan cuellos de botella en el servicio a la mesa[cite: 4].
* **Problema:** La sobrecarga del personal de servicio genera retrasos observables en la atención y una experiencia negativa[cite: 4].
* **Justificación:** Agilizar el servicio beneficia a los dueños aumentando la rotación de mesas y reduce la sobrecarga del personal. También mejora la experiencia de servicio del cliente[cite: 4].

## Objetivos
**Objetivo General:** Desarrollar un bot de asistencia web para agilizar los tiempos de atención en mesa en restaurantes pymes[cite: 4].

**Objetivos Específicos:**
1. Diseñar la interfaz web del bot[cite: 4].
2. Integrar las notificaciones con la cocina[cite: 4].
3. Medir tiempos de respuesta[cite: 4].

## Alcance
* **Incluye:** Aplicación web accesible mediante código QR para iniciar un chat con el bot de asistencia que tendrá la capacidad de dar información del menú, tomar pedido, calcular costo de pedido, calcular tiempo estimado de pedido[cite: 4].
* **Fuera de Alcance:** Pasarelas de pago electrónico, facturación e integración con otros servicios contables de la mesa[cite: 4].

## Mapa de Ciclo de Vida del Desarrollo

### 1. Contextualización
* **Pregunta:** ¿Qué problema existe y quién lo vive?[cite: 6]
* **Evidencias:** Diagnóstico de la demora y congestión en la atención de mesas durante horas pico[cite: 4]. Listado de stakeholders: Propietarios, meseros, comensales y el equipo de desarrollo[cite: 4].

### 2. Requisitos
* **Pregunta:** ¿Qué debe hacer y bajo qué condiciones?[cite: 6]
* **Requisitos Funcionales (RF):** El bot debe dar información del menú, tomar pedido, calcular costo y calcular el tiempo estimado del pedido[cite: 4].
* **Requisitos No Funcionales (RNF):** El sistema debe funcionar fluidamente en navegadores móviles estándar (HTML5) sin instalar aplicaciones nativas[cite: 4].
* **Evidencias:** Documentación de RF, RNF e historias de usuario[cite: 6].

### 3. Diseño
* **Pregunta:** ¿Cómo se organizará la solución?[cite: 6]
* **Evidencias:** Diseño de la interfaz web del bot y la arquitectura para integrar las notificaciones con la cocina[cite: 4].

### 4. Construcción
* **Pregunta:** ¿Cómo se implementa?[cite: 6]
* **Evidencias:** Código fuente de la aplicación web en HTML5[cite: 4], junto con el registro de ramas y commits del desarrollo[cite: 6].

### 5. Pruebas
* **Pregunta:** ¿Cumple lo esperado?[cite: 6]
* **Evidencias:** Casos de prueba para medir tiempos de respuesta y evaluar la latencia del servidor[cite: 4]. Resultados y reporte de defectos[cite: 6].

### 6. Entrega
* **Pregunta:** ¿Qué versión se libera?[cite: 6]
* **Evidencias:** Aplicación web accesible mediante código QR[cite: 4]. Manuales de usuario y notas de la versión[cite: 6].

* **Predictivo:** Planificación más detallada al inicio[cite: 6].

## Roles
* **Stakeholder/cliente:** Propietarios de los restaurantes[cite: 4, 6].
* **Usuario:** Comensales del restaurante y personal de servicio (meseros y equipo de cocina)[cite: 4, 6].
* **Equipo de desarrollo:** Encargados de la construcción de la aplicación[cite: 4, 6].
* **Responsable del producto / Líder:** Coordina el proyecto y define el valor a entregar[cite: 6].
* **Responsable de pruebas/calidad:** Encargado de verificar los tiempos de respuesta y probar la latencia del servidor[cite: 4, 6].
